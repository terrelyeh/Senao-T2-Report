TICKET #105248819
Confirmation Regarding Behavior When a Pro Plan License Expires
Opened: Jun 1, 2026 Last Response: Jun 9, 2026 Closed: Jun 10, 2026
Resolved
Case Description

We have received an inquiry from a customer regarding the behavior when a license expires. Could you please provide information on the following?

Q1: According to the "Will the device be still functional when the license is expired?" section on https://www.engenius.ai/cloud/licenses, it states that even if a PRO feature plan license expires, the device will continue to function the same way it did before the license expiration. Does the same apply to the entire Cloud environment? For example, can all features such as log retention, alert notifications, and diagnostic tools continue to be used in the same way? Is the only difference that configuration changes can no longer be made?

Q2: If a PRO license expires and is changed to a BASIC license, how are the feature differences reflected? For example, if a network is using 1,000 whitelist entries and is downgraded to BASIC, how is the limit reduced to 300? After changing to BASIC, are log data older than the previous day deleted immediately?

Q3: If there is any documentation describing the impact of changing a license from PRO to BASIC, please share it.

Case Summary

1. What Happens Immediately Upon PRO License Expiration?

  • Device Functionality: The device will continue to function normally using its last applied configuration.
  • Management & Configuration: The device becomes completely unmanageable and unconfigurable via the EnGenius Cloud platform. No settings changes can be made.
  • Cloud Features: Real-time monitoring, telemetry, log retention, alerts, and remote diagnostic tools are cut off for that specific device.

2. What Happens if Downgraded to a "BASIC" Plan?

To regain management capabilities without buying a new PRO license, the organization can manually switch the device/organization feature plan to BASIC under Org → Inventory & License. Doing so immediately applies BASIC tier limits:

  • Feature Limits: Whitelist/VIP client entries are reduced from 1,000 (PRO) to 300 (BASIC) — only the first 300 remain manageable.
  • Data Retention: Statistics retention drops from 30 days (PRO) to 1 day (BASIC) (or 7 days for cameras). Any older data is deleted/hidden immediately.
  • Alerts & Diagnostics: Advanced alert notifications and full diagnostic tools (like packet capture) are downgraded to basic, limited versions.

3. Per-Device License Scope

  • Isolation of Impact: Licenses are managed on a per-device basis. Even within the same network, only the specific devices with expired licenses will lose management capabilities; other devices with active PRO licenses will continue to function and be managed with full PRO features.
TICKET #107571679
Device and Cloud Session
Opened: Jun 10, 2026 Last Response: Jun 12, 2026 Closed: Jun 12, 2026
Resolved
Case Description

Does the device keep a TCP session open with the cloud?

Case Summary

The KOKOMO Support team inquired whether KOKOMO-AP and KOKOMO-SW devices maintain persistent TCP sessions with the cloud, noting that configuration updates reflect very quickly. They wanted to know if this was due to active connections (like WebSocket) or just coincidental timing with periodic syncs.

Key Details & Answers

  • Persistent Connection: Yes. Even when idle and not actively using diagnostic features (Diagnosis Tools), both KOKOMO-AP and KOKOMO-SW maintain a persistent TCP session with the cloud using the WebSocket protocol. This allows configuration changes to be pushed instantly when the "Apply" button is pressed, rather than waiting for a periodic check-in.
  • Session Count: Under normal standby and operating conditions, each device occupies only 1 concurrent TCP session. All real-time communication and diagnostic data share this single channel to minimize the firewall load.
TICKET #108782519
About Changing the HTTP/HTTPS Proxy Settings
Opened: Jun 15, 2026 Last Response: Jun 22, 2026 Closed: Jun 22, 2026
Resolved
Case Description

After changing the HTTP/HTTPS proxy settings on the wireless AP (from 10.254.3.12:8080 to 10.254.3.11:8080), the device became offline.

  • In other networks, there are devices configured with 10.254.3.11:8080 that are operating normally, and these devices have not had their settings changed.
  • In the same network as the affected AP, there are also devices configured with 10.254.3.11:8080 that are operating normally.
  • After applying the settings, it has been confirmed on the local web page that the configuration is properly reflected.

The procedure followed was: (1) log in to the local web interface, (2) navigate to Local Settings → Web Proxy Settings, change the setting, and click "Apply".

We would appreciate your confirmation on: is there any issue with the above procedure, and when the proxy settings are changed, are they properly applied internally as well?

Case Summary

The Issue

An APRESIA customer's wireless Access Point (AP) went offline after changing its HTTP/HTTPS proxy settings via the local GUI from 10.254.3.12:8080 to 10.254.3.11:8080. Other devices on the same and different networks configured with the new proxy were operating normally. The local AP interface correctly reflected the new configuration, but the device remained offline even after a reboot or after attempting to revert to the original configuration.

Investigation & Troubleshooting

  • Connectivity Check: The customer confirmed that there was no communication to the internet/cloud (Local status: Gateway OK, Internet NG, Cloud NG). No connection logs were showing up on either the old or new proxy server during the failure.
  • Escalation: The ticket was proposed to be escalated from T1 (Backend Support) to a T2 Issue Report to involve R&D support for deeper LAN and proxy analysis.

The Resolution

The issue was successfully resolved in the customer's environment by toggling the proxy checkbox settings in the local GUI:

  • Unchecked the "HTTP/HTTPS Proxy" option under Web Proxy Settings and clicked Apply.
  • Re-checked the "HTTP/HTTPS Proxy" option, entered the new proxy IP address (10.254.3.11), and clicked Apply again.

Key Takeaway

  • Expected Behavior: By design, the checkbox (enable/disable) and the Address/Port fields are independent. Toggling the checkbox should not be required to change the proxy destination.
  • Conclusion: This was an isolated incident. Support confirmed they have not received similar reports from other customers, and both support teams were able to switch proxies successfully in test environments without needing to toggle the checkbox. The ticket was closed as resolved.
TICKET #109078649
How to Check an SFP Serial Number
Opened: Jun 16, 2026 Last Response: Jun 17, 2026 Closed: Jun 29, 2026
Resolved
Case Description

To the best of my understanding, there is currently no way to do so. However, is there any method to check the serial number of an SFP connected to a port from the cloud?

It would also be acceptable if the serial number can be obtained indirectly through a report or another feature.

Case Summary

The Issue

A support team member (峯村@KOKOMOSupport) inquired on behalf of a customer (APRESIA) about whether it is possible to check the serial number of an SFP module connected to a switch port directly from the cloud or via a report.

Resolution & Key Takeaways

  • Cloud Limitation: SFP serial number details cannot currently be viewed directly on the Cloud dashboard.
  • Alternative Method: These details can only be accessed via the switch's Local GUI or CLI.
  • EnGenius Cloud Workaround: EnGenius Cloud supports a Remote Local GUI feature, which allows users to securely log into the switch's Local GUI remotely to check SFP configurations (found under Monitor → SFP Module Information).
  • Next Steps: Because this Remote Local GUI feature is not yet synchronized or implemented in the KOKOMO platform, the support team plans to contact the PLM team to request feature parity with EnGenius Cloud.

The case was resolved and closed as the workaround successfully allowed them to retrieve the SFP serial number.
